> R-01 Reviewer note: The runtime guard now classifies issuers by generic rules (http scheme, .invalid/.local/localhost, single-label host, loopback or private address) and requires APP_ENV=local. The API binds 0.0.0.0 in its container, and host exposure is limited to 127.0.0.1 with a slice-check assertion.

> R-02 Reviewer note: The patch identity is computed from the merge-base to HEAD and excludes docs/security-reviews/. A READY verdict is required, and the initial path list is stated and includes the list file, the scripts and the workflows.

> R-03 Reviewer note: Publish is serialized by one lock and uses a compare-and-set on currentVersionId inside the transaction. The publishedAt timestamp T is stored with the committed version. The compensation is conditional, and reconciliation runs at start-up and before every Publish.

> R-04 Reviewer note: /docs, /redoc and /openapi.json are disabled, and a route-enumeration test asserts that only /health lacks require_owner.

> R-05 Reviewer note: Refreshes on an unknown key id are limited to one per 60 seconds, with a test.

> R-06 Reviewer note: The validator holds only generic rules, and the fake issuer URL lives only in local/compose.env, so the build guard and runtime guard do not conflict.

> R-07 Reviewer note: Component jobs plus an always-run gate job are described, with explicit pass and skip semantics.

> R-08 Reviewer note: currentVersionId, the relative link target and the initial empty-release state are specified in REL-0.1. The earlier functional-design entity file only has the relationship and is not changed here, which is acceptable for this stage.

> R-09 Reviewer note: CORS, the token flow, eslint-plugin-react, the HSTS rationale and the NFR13.4 and NFR13.5 designs are now present.
