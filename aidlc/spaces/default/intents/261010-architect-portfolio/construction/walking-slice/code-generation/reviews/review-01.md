What held up under attack: require_owner is attached at router level and only /health is outside it; docs, redoc and openapi are off; the algorithm allow-list, key-to-algorithm match, iss, aud, exp, iat and sub checks are all enforced, and key-fetch failure is fail-closed (401). The fake issuer holds its ES256 key only in memory, carries the marker, and sits under local/; the API refuses a local-class issuer without APP_ENV=local. Publish is serialized, checks the reviewed revision against the project twice (before and in the compare-and-set transaction), writes the release before the swap, renames the temporary link atomically, compensates conditionally, and reconciles from the database at start-up and before each Publish. Snapshot data is validated by Pydantic and again by Ajv, the renderer output (page paths, image variants, static asset names) is re-validated in Python before anything is written, and React escaping with no inline script is used. Workflows have top-level read-only permissions, SHA-pinned actions, no pull_request_target, persist-credentials off and head-SHA checkout; the gate fails on zero-file scans and skipped required jobs. No private keys or tokens were found by pattern search (gitleaks is not installed on this host). CORS allows only the configured Studio origin, logs are redacted, and uvicorn access logs are off.

Verdict basis: no Critical finding; two Major findings (inside the READY limit of two); the rest are Minor. The Major findings concern the review gate that the team practice relies on for the lock Bolts S0 to S3, so I recommend fixing both before the S1 to S3 branch is relied on, and at the latest before S0 merges.
