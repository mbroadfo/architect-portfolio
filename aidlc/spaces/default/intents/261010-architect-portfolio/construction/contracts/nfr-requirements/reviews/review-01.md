### Notes

The omission of the performance, scalability, reliability and observability files is correct. The stage file's `produces_kinds` limits them to `service` and `ui` units, and U1 is `spec`. The security and tech-stack files, and `traceability.json`, are unfiltered, so U1 produced all it is required to. The single performance figure in the security file follows U0's precedent.

Checked and found sound: all 17 upstream NFRs are enumerated in `traceability.json`. The four `N/A` entries (NFR5, 7, 9, 10) are justified, with owners named. The 21 error codes match the approved `ErrorCode` list. The no-version-claim approach in the tech stack avoids unrecorded versions, and its baseline matches U0 (Python 3.12, Node 22, FastAPI, PyJWT, pytest, Vitest, Playwright). The R-07 prefixes, the 18 key cases, the three storage channels, the determinism and supply-chain requirements and the secrets handling all trace to the Functional Design.

Other points that did not rise to findings:
- The generated Python types from datamodel-code-generator format through Black. The chosen formatter and the drift check must agree with the repository's Ruff format.
- The maximum-size benchmark fixture (5 MB) should be generated at test time and not committed.
- The browser "no `unsafe-eval`" test must apply the Studio policy as a real header or meta tag, so a violation is observable.

Three Major findings exceed the limit of two, so the verdict is NOT-READY. All are fixable within this stage without changing approved records.
