# Security Requirements — U1 contracts

**Inputs:**
- functional-spec, rules and entities: `../functional-design/`;
- requirements (NFR1 to NFR17);
- contract-summary (C1 to C11; R-07, R-08, R-18);
- team-practices (Testing Posture, Code Style, Deployment);
- `bolt-plan.md`, Bolts B01 and B02;
- `nfr-requirements-questions.md`.

U1 is a specification unit. It has no runtime, no deployment and no data. It delivers specs, generated Python and TypeScript types, validators, fixtures, and a shared contract-test harness with a test-only reference host. Its non-functional requirements are therefore about the boundaries it specifies (so that other units can be held to them), about the safety of what it ships (fixtures, keys, dependencies), and about the quality gates its own code meets. Every requirement row carries its inception NFR ID with a sub-number. The performance, scalability, reliability and observability documents are not produced for a `spec` unit (Q1).

## Assumptions & Open Questions

- **Licence report is a proposal.** NFR13.7 is a recorded report and an optional verify-check entry. Making it a required merge gate is a tracked proposal for Michael through the CI Pipeline stage; nothing in U1 depends on it being required.
- **BR9.4 and GitHub URLs.** BR9.4 says fixture hosts use `.invalid`. The approved C2 requires github.com profile and repository URLs, so NFR3.2 allows exactly those forms with a placeholder owner. This reads BR9.4 together with C2 and changes neither.
- **Derived allocations.** The 3-minute share of the 10-minute CI total (NFR13.2), the 250 ms Python validation figure (NFR6.1), the 1-second browser ceiling (NFR6.2) and the nesting depth of 16 (NFR13.12) are this stage's own allocations of approved totals or of the approved contract shapes (the team CI budget, NFR6, C2), not approved figures themselves. NFR Design may revise them from measured data. The 8-times scaling bound and its sample sizes (NFR13.8) are fixed here and replaced by `DOWNLOAD_NAME_BUDGET` when NFR Design sets it.
- **Not produced for a spec unit.** NFR5, NFR7, NFR9 and NFR10 have no requirement in U1 (see `traceability.json`). The slice's pattern applies: the owning units set those targets.
- **Test-only code is local.** The harness issuer and reference host sit outside every deployable target; the exact path is chosen at code generation.
