## Visual Direction

The crafted studio identity (CR-04, D-26, FR9.6):

- **Colour:** warm charcoal surfaces with brass accents.
- **Type:** an editorial serif display face (Cormorant Garamond) for titles, a reading serif (Source Serif 4) for narrative, and a clean sans (Inter) for interface text.
- **Imagery:** large, cinematic image fields blended into the copy column.
- **Interaction:** restrained — gentle image scale on hover, no autoplay, no parallax.

Tokens, components and responsive rules are in `design-system-mapping.md`. All fonts are self-hosted under the SIL Open Font License, so the public site requests nothing from third-party origins (FR9.5, NFR15).

### P4 — Approved-Publication Snapshot (simulated public export)

Screenshots: `export-home-*`, `export-catalog-*`, `export-category-games-*`, `export-project-stars-*`, `export-project-baduk-*`, `export-route-monopoly-*`.

The public site is built only from an **approved-publication snapshot** (FR7.1, FR7.4, FR10.1, NFR2). In the prototype:

- **The approval model** lives in `data.js` as one `publication` record per project: status, content approval, rights review and live-URL authorization. The Studio reads its statuses from the same record.
- **The publication rule:** a project is exported only if it has a published version, its content is approved, and no rights review is outstanding. Its live URL is exported only if authorized.
  - STARS and Baduk carry **simulated** approvals so the export can be demonstrated; Michael has approved nothing for publication.
  - Monopoly Arena (rights review outstanding) and Risk (draft, live URL withheld) are excluded.
- **The build:** `tools/build-export.cjs` writes `export/publication.js` and copies the pages, styles, scripts, fonts and **only the assets the approved projects use**. Export pages load `publication.js` and never `data.js`. The snapshot holds only allow-listed fields (FR4.10): title, summary, category, featured position, highlights, images, narrative, derived badge labels, the authorized live URL, and public repositories with their licence. It holds no publication state, access internals or private repositories.
- **One source:** the featured carousel (2 items), category tiles and counts (Games & AI Arenas 1, Astronomy & Exploration 1), catalog and category pages, case studies and direct routes all derive from the snapshot. A direct route to an unapproved candidate (`export/project.html?p=monopoly-arena`, `?p=risk`) shows "This exhibit isn't on display".
- **Regression checks:** the X-* checks (see `verification.md`). They scan every file in the export payload for the unapproved candidates' names, slugs, live hosts and assets; check the snapshot schema and the exact asset set; and confirm that every export route's rendered page and in-memory data contain no unapproved information, with no request leaving `export/`.

## Assumptions & Open Questions

- **Owner inputs before launch:** real imagery and approved copy for each candidate; biography; contact email address.
- **Owner decisions** (D-28; none is approved by this design): the trademark and artwork review for Monopoly and Risk; licensing for STARS and Monopoly; authorizing Risk's live URL after its privacy and security review; publication approval of each candidate.
- **Prototype limits:** pages are rendered client-side from `data.js`, while production pre-renders them at export (FR7.4). The prototype cannot set HTTP status codes, headers or CSP; those are verified in implementation (NFR15). Studio behaviour is simulated in memory.
- **Later stages:** the AI provider, GitHub credential mechanism, secure edit recovery, exact rate limits, image pixel limit and the link-check isolation design belong to Domain, NFR and Infrastructure Design.
